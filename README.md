# نظام إدارة المكاتب والموظفين · أبناء فارس أبو زايد

نظام واحد لكل الفروع: الفروع، والموظفين، والصلاحيات المتسلسلة، ولاحقاً الحضور والرواتب والمراسلات وكل أقسام نظام «مخيم 2».

- `backend/`: Laravel 13 (PHP 8.3+) + MySQL/MariaDB. الـAPI تحت `/api`.
- `frontend/`: React + TypeScript (Vite)، بنفس شكل نظام مخيم 2.
- `docs/01-database-design.md`: مخطط قاعدة البيانات والقرارات.

## التشغيل محلياً

```bash
# الباك إند
cd backend
cp .env.example .env        # عدّل DB_DATABASE / DB_USERNAME / DB_PASSWORD
composer install
php artisan key:generate
php artisan migrate
php artisan serve           # http://127.0.0.1:8000

# الواجهة (بشاشة ثانية)
cd frontend
npm install
npm run dev                 # http://localhost:5173 (بتحوّل /api للباك إند)
```

أول ما تفتح الموقع على قاعدة فاضية بتطلع شاشة «تجهيز النظام»، وفيها بتعمل حساب السوبر أدمن.
أو من السيرفر: `php artisan app:super-admin <اسم-المستخدم> --name="الاسم"`. هالأمر كمان بيرجّع الدخول لو انقفل الحساب.

## الاختبارات

```bash
cd backend && php artisan test     # بتشتغل على قاعدة af_office_test (MariaDB)
cd frontend && npx tsc --noEmit
```

## المرحلة 1 (هلأ)
- الدخول باسم مستخدم ورمز. بعد 5 محاولات غلط الحساب بيتقفل 15 دقيقة.
- الحساب الجديد بياخد رمز مؤقت، وصاحبه لازم يغيّره أول ما يدخل.
- الفروع، وأقسام كل فرع (فتح وتسكير)، ودوامات الفرع (الجمعة دوام)، والعطل، والأقسام.
- المستخدمين حسب الفرع والمستوى. ما حدا بيدير حساب بمستواه أو أعلى منه.
- شاشة الصلاحيات: لكل دور، واستثناءات لشخص، بثلاث مستويات (إله بس / فرعه / كل الفروع).
- سجل الحركات لكل تعديل حساس.

## المرحلة 2 (هلأ)
- **ملف الموظف:**
  - البيانات الشخصية والمحفظة أو البنك: الموظف بيعدّلها بنفسه.
  - البيانات الوظيفية والراتب: بتحددها شؤون الموظفين.
  - المرفقات: صور أو PDF.
  - الحالة (فعّال، متدرب، موقوف، مفصول) مع سجلها. المفصول ما بيقدر يدخل على النظام.
- **الحضور:**
  - زر بالرئيسية بيشتغل من أي مكان، وQR لكل فرع.
  - مسحتين باليوم كحد أقصى، والانصراف ما بينسجّل قبل ساعة من الحضور، ومسحتين ورا بعض خلال دقيقتين بينحسبوا وحدة.
  - شبكة المكتب للـQR بيعتمدها مدير الفرع. والمسافة عن المكتب فحص اختياري.
  - التأخير والإضافي بينحسبوا لحالهم حسب الدوام. الجمعة دوام، والعطل الرسمية بتنحسب.
  - مدير الفرع بيشوف لوحة الفرع، وبيعتمد، وبيعدّل، وبيدخل الحضور يدوي. كل تعديل بينحفظ بسجل.
- **بدون نت:**
  - النظام بينحفظ على الجوال وبيفتح بدون إنترنت.
  - زر الحضور بيحفظ الضغطة بوقتها، وبيبعتها لحاله لما يرجع النت، والسيرفر بيعدّها مرة وحدة.

بعد ما تسحب تحديث (`git pull`):
```bash
cd backend && composer install && php artisan migrate && cd ..
cd frontend && npm install && cd ..
```

**ملاحظة للاستضافة:** شبكة المكتب بتعتمد على عنوان الإنترنت اللي بيشوفه السيرفر. إذا الاستضافة ورا Cloudflare أو بروكسي، لازم نضبط Laravel يقرأ العنوان الحقيقي (TrustProxies)، وهاد بنعمله وقت الرفع على الاستضافة.

## المرحلة 3 (الآن)
- **الرواتب:**
  - **قواعد الحساب:** خصم التأخير، وخصم الغياب، والوقت الإضافي. لكل منها: لا يُحسب، أو حسب الأجر، أو مبلغ ثابت. وتسري القاعدة من تاريخ يحدده مسؤول شؤون الموظفين.
  - **الخصومات والمكافآت اليدوية:** تدخل في أول دفعة من الشهر المحدد.
  - **السلف:** تُسدَّد بقسط من كل دفعة.
  - **دفعة الرواتب:** نسبة من راتب الشهر، مثل 50%. يُحسب الحضور في الدفعة التي تُكمل الشهر (100%). مراحلها: مسودة، ثم اعتماد، ثم صرف.
  - **الإخراج:** تصدير كشف الصرف إلى Excel، وطباعته.
  - **«رواتبي»:** يرى فيها الموظف دفعاته المعتمدة وتفاصيلها.
  - **الاعتماد:** صلاحية «اعتماد دفعات الرواتب»، يوزّعها السوبر أدمن من شاشة الصلاحيات. تملكها مبدئياً الإدارة وشؤون الموظفين.
- **المراسلات:**
  - **الصناديق:** الوارد، والمرسل، والأرشيف، مع البحث، وشارة بعدد الرسائل غير المقروءة في القائمة.
  - **الرسائل:** رسالة جديدة، ورد، ورد على الجميع، ورفع (تحويل)، ومرفقات.
  - **نماذج جاهزة:** «طلب إجازة» (من تاريخ إلى تاريخ)، و«طلب إذن» (يوم ومن ساعة إلى ساعة).
  - **من يراسل من:** الموظف يراسل مدير فرعه وشؤون الموظفين فقط. مدير الفرع يراسل فرعه وشؤون الموظفين والإدارة. شؤون الموظفين والإدارة والسوبر أدمن يراسلون الجميع. والمراسلة الجماعية (فرع أو قسم أو الجميع) بصلاحية مستقلة.

**نقطة مفتوحة:** من يعتمد دفعات الرواتب نهائياً؟ هل نضيف دور «المالية» مستقلاً؟

## المرحلة 4: المهام الميدانية
- **لوحة المكتب:** أربعة أعمدة (لم تُرسل، عند الفني، قيد التنفيذ، أُنجزت أو أُلغيت). لكل مهمة مفتوحة عدّاد وقت وشريط يحمرّ عند التأخر. وفيها تنقّل بين الأيام، وبحث برقم المهمة أو المشترك أو الفني.
- **مهمة جديدة بنقرات قليلة:** النوع، والفني أو عدة فنيين (يظهر عدد مهام كل فني المفتوحة)، والمشترك، والمنطقة، والأولوية، والمدة. ثم: حفظ وإرسال واتساب، أو إرسال داخل النظام، أو حفظ دون إرسال (تحضير).
- **صفحة المهمة:** التفاصيل، وزر واتساب لكل فني، وتغيير الفني قبل البدء، وتسجيل الإنجاز عن الفني، والإلغاء مع السبب، والسجل الكامل، ونسخ الرابط الخاص.
- **«مهامي» للفني:** بطاقات كبيرة وزرّان: «بدأت العمل» و«أنجزت المهمة»، مع ملاحظة وصورة اختيارية. تعمل دون إنترنت وتُرسل وحدها عند عودة الاتصال. وشارة بعدد المهام الجديدة.
- **الرابط الخاص `/t/...`:** يفتحه الفني من واتساب **دون تسجيل دخول**.
- **الأنواع والمناطق:** لكل فرع. ونُقلت أنواع المهام الستة عشر من نظام مخيم 2.
- **القواعد كما في النظام القديم:** لا يتغيّر الفني بعد البدء. المهمة المشتركة يُنهيها المكتب. الرقم متسلسل لكل فرع. و«متأخرة» تظهر تلقائياً.
- **لاحقاً:** ربط المهمة بالأختام (مع قسم الأختام)، وإرسال SMS الآلي (مع قسم الرسائل).

## بيانات تجريبية (لجهاز التجربة فقط)
`demo.bat` (أو `php artisan app:demo` من مجلد `backend`) يضيف:
- **الفروع التسعة:** غزة، والنصيرات، والمخيم الجديد، ومخيم 2، والسوارحة، والزوايدة، والمغازي، ودير البلح، والبريج.
- **الأشخاص:** في كل فرع مدير، ومحصّلان، وثلاثة فنيين (أحدهم بيومية)، ومتدرب. ومعهم حساب شؤون الموظفين وحساب الإدارة.
- **الحضور:** شهران فيهما تأخير وغياب ووقت إضافي، وحضور اليوم.
- **الرواتب:** قواعد الحساب، وخصومات ومكافآت وسلف، ودفعات لثلاثة فروع (الأولى مصروفة والثانية مسودة).
- **المهام:** مهام اليوم بكل حالاتها في كل فرع.
- **المراسلات:** طلب إجازة، وطلب إذن، ورسالة مرفوعة إلى الإدارة، وتنبيه لفرع كامل.
